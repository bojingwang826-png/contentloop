# ContentLoop 小红书本机发布助手

这是仅供本人安装的 Chrome Manifest V3 扩展。网站先完成七页 PNG 的生成与质检，再通过浏览器内部消息交给扩展。扩展打开小红书创作服务平台的“上传图文”页面，用该浏览器现有的登录状态带入七张图片、标题和正文，然后停在可编辑的草稿页面。最后的“发布”按钮只由用户本人点击。扩展不读取或保存账号密码、Cookie、访问码，也不把 PNG 上传到 ContentLoop 服务端。

## 安装与使用

1. 在 Chrome 地址栏打开 `chrome://extensions`，启用“开发者模式”，点击“加载已解压的扩展程序”，选择这个 `chrome-extension` 文件夹。安装扩展是持久访问授权，请先检查 `manifest.json` 中允许访问的站点。
2. 在**同一个 Chrome**中登录 `https://creator.xiaohongshu.com/`，确认可手动打开图文发布页。不要把账号密码给 ContentLoop。
3. 打开 `https://contentloop.pocketbay.app/#/export`。核对页面事实与版本，编辑小红书正文，点击“一键带入小红书”，确认推荐标题与正文。
4. 扩展会打开小红书图文发布页，等待目标标签出现可信的小红书地址后明确注入本机脚本；Chrome 会在页面就绪时执行注入，扩展再检查脚本有回应并带入素材，不额外等待标签状态为 `complete`。页面右上角会显示“正在带入”、成功或具体失败原因；若后台在带入前失败，也会尝试在已打开的可信小红书页面显示原因。你可以在小红书页面删改图片、标题和正文，核对后手动点击“发布”。若页面显示“自动带入未完成”，先检查已打开的页面；已有图片时不要直接重试，避免重复添加。

本扩展只在 PocketBay 为原项目加载的应用内嵌域名 `contentloop--e.pocketbay.app` 及本地开发地址自动加载网站脚本；小红书脚本仅在用户点击带入、后台核对页面确属 `creator.xiaohongshu.com` 且已加载后，通过 Chrome 的 `scripting` 能力注入。没有新增可访问站点；外层 `contentloop.pocketbay.app` 仍用于核对标签来源。网站探测会真正检查扩展后台，而非只检查内容脚本。小红书网页结构可能调整，自动上传或填写可能因此中断；代码不会点击小红书最终“发布”按钮，也不会自动重试部分失败的草稿。

修改扩展代码后，到 `chrome://extensions` 点击此扩展的“重新加载”，确认版本为 `0.2.4`，**关闭旧的 ContentLoop 标签页，再新开** `https://contentloop.pocketbay.app/#/export`。Chrome 的扩展“错误”页会保留历史记录；若需判断新版本是否还报错，先清除旧错误记录再在新页面重试。
