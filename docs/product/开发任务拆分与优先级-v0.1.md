# 开发任务拆分与优先级 v0.1

## 1. 开发策略

采用“先完成一条可演示竖切，再逐步接入真实能力”的顺序。第一阶段不先做全套搜索、知识库和模型集成，而是用匿名化样例走通：

`选题卡 → 研究页 → 七页大纲 → 编辑器 → PNG／ZIP 导出`

这条竖切完成后，项目已经可以给面试官体验；后续接入 AI、Obsidian 和真实复盘时，不推翻页面与数据结构。

## 2. 优先级定义

- P0：没有它就无法展示核心闭环。
- P1：让产品从静态 Demo 变成真实可用工具。
- P2：增强作品集说服力，但可以在第一轮上线后补充。
- 不做：MVP 明确排除，防止 vibe coding 失控。

工作量只使用相对等级：S（小）、M（中）、L（大）。对初学者而言，遇到外部 API、浏览器文件权限和图片导出通常需要额外调试时间。

## 3. 里程碑总览

| 里程碑 | 目标 | 优先级 | 结果 |
| --- | --- | --- | --- |
| M0 | 工程与设计骨架 | P0 | 能打开五个空页面 |
| M1 | 匿名样例竖切 | P0 | 不调用 AI 也能完整演示 |
| M2 | 七页编辑与版本保护 | P0 | 能改、锁、重写、恢复 |
| M3 | PNG／ZIP 与导出检查 | P0 | 能生成发布包 |
| M4 | AI 适配层与结构化生成 | P1 | 真实生成不破坏编辑器 |
| M5 | 来源研究与事实核验 | P1 | 研究页能追溯证据 |
| M6 | Obsidian 受控写回 | P1 | 知识真正沉淀 |
| M7 | 发布数据 OCR 与复盘 | P2 | 展示学习闭环 |
| M8 | 在线 Demo 加固 | P0/P1 | 面试官稳定体验 |

## 4. M0｜工程与设计骨架

### 目标

建立单一 TypeScript 全栈项目、基础导航、主题和测试框架。

### 任务

- [ ] 初始化 Next.js App Router＋TypeScript 工程。
- [ ] 配置代码质量、格式化、单元测试和端到端测试。
- [ ] 建立 `src/domain`、`src/features`、`src/components`、`src/lib`、`src/server`、`public/assets` 等清晰目录。
- [ ] 建立深色金色设计 token：背景、表面、文字、强调色、功能色、间距、圆角和阴影。
- [ ] 建立五页面路由：首页、研究、大纲、编辑、导出。
- [ ] 建立统一顶部步骤导航与任务状态。
- [ ] 加入匿名样例入口和个人模式入口占位。

### 验收

- 五个页面可以互相导航，刷新不报错。
- 页面在常见桌面宽度和手机预览宽度下不横向溢出。
- 没有任何 API 密钥进入前端包。

工作量：M。

## 5. M1｜匿名样例竖切

### 目标

使用固定 JSON 样例展示完整产品价值，不依赖模型、搜索和 Vault。

### 任务

- [ ] 按 Schema 建立 `铲友装备课01` 匿名样例数据。
- [ ] 首页展示 5 张样例选题卡和 1 个热门阵容模块。
- [ ] 研究页展示为什么值得做、3 个观点、证据状态和推荐理由。
- [ ] 大纲页展示七页目标、顺序和所需素材。
- [ ] 编辑页加载七页样例，支持切换页面与实时预览。
- [ ] 导出页展示标题候选、正文、标签和导出检查。
- [ ] 所有实时按钮在样例模式有明确行为，不能出现无法点击的假按钮。

### 验收

- 新访客无需注册、无需模型额度，可在 3 分钟内走完一次完整流程。
- 页面明确标记样例数据日期，不伪装成今日实时结果。
- 刷新浏览器后仍能从本地恢复当前样例草稿。

工作量：L。

## 6. M2｜七页编辑与版本保护

### 目标

实现最能体现产品设计价值的编辑器，而不是自由画布。

### 任务

- [x] 用一个结构化 `SevenPageDocument` 驱动编辑与预览。
- [x] 实现字段编辑、页面切换和实时预览。
- [x] 手改满意后可明确标记“已保留”，AI 重写自动跳过。
- [x] 实现锁定／解锁整页。
- [x] 实现局部重写与整体重写的 mock 版本，验证字段白名单机制。
- [x] 实现装备卡上移／下移和手动顺序保护。
- [ ] 修改页头问题后提示是否重新排序，默认保留手动顺序。
- [x] 每次重写前建立版本点；支持撤销、重做和恢复。
- [ ] IndexedDB 保留最近 20 个自动版本和不限数量的命名版本。
- [x] 命名版本支持自定义名称、改名和按创作步骤筛选。
- [x] 删除命名版本前二次确认，并支持撤销删除。
- [x] 实现观点切换影响清单和逐页“保留／重写”。
- [x] 检测旧内容与新观点的直接矛盾并生成导出阻塞项。

### 验收

- 锁定页和手改字段不会被整体重写覆盖。
- 只允许重写请求中明确列出的字段路径。
- 恢复旧版本后页面、锁定状态、手动顺序和素材引用一致。
- 首篇第 3～6 页每页固定 3 张纵向装备卡，手机预览可读。

工作量：L。

## 7. M3｜模板渲染、PNG／ZIP 与导出检查

### 目标

把结构化七页内容可靠变成可发布文件。

### 任务

- [x] 预览与导出共用同一个 3:4 页面渲染模型。
- [ ] 建立收藏型教程模板和版本攻略模板。
- [x] 建立首篇需要的封面、合成树、装备功能页和口诀页变体；站位页、时间线页待后续模板补充。
- [ ] 接入预置官方装备图标与 6～8 张内置背景。
- [x] 确保官方图标按原比例显示，不改色、不变形。
- [x] 导出前等待字体和图标加载完成；独立背景资产接入后沿用同一等待机制。
- [ ] 检查文字溢出、缺失素材、低清素材和字体加载。
- [ ] 沿事实引用图检查本篇实际展示字段。
- [ ] 生成可跳转的问题清单。
- [x] 生成单页 PNG 和七页 PNG ZIP；结构化草稿、发布文案和标签暂时分别下载／复制。
- [ ] 支持带“待核验”标识的内部草稿导出。

### 验收

- 七张图片尺寸和命名正确。
- 页面预览与导出结果视觉一致。
- 导出过程中不向服务器上传最终 PNG。
- 有阻塞问题时不能生成无标识正式发布包。
- 第 2 页完整合成树在导出图中保持高清，并可在工具内放大查看。

工作量：L。

## 8. M4｜AI 适配层与结构化生成

### 目标

接入真实模型，同时让编辑器不依赖具体厂商。

### 任务

- [ ] 服务端建立统一 `AiTaskRequest/AiTaskResponse` 接口。
- [ ] 用 Zod 为每类任务定义输入输出。
- [ ] 实现任务：理解输入、研究蒸馏、选题评分、大纲、七页生成、字段重写、影响分析、发布文案、复盘分析。
- [ ] 所有请求传入允许使用的来源、事实和素材 ID 白名单。
- [ ] 校验失败后自动修复或重试一次。
- [ ] 第二次失败时保留旧稿并给出可读错误，不覆盖任何内容。
- [ ] 设置请求频率、访客额度和每日总额度。
- [ ] 为开发与测试提供确定性的 mock provider。
- [ ] 图片模型仅用于用户主动点击“生成新背景”；默认 Demo 不依赖图片模型。

### 验收

- 更换模型 provider 不修改编辑器和领域类型。
- 模型返回越界字段、未知 ID 或第八页时被拒绝。
- 没有证据的数字和实测叙述无法进入正式输出。
- 访客额度用尽仍能使用样例、编辑和导出。

工作量：L。

## 9. M5｜来源研究与事实核验

### 目标

把“为什么值得写”和“这条结论能不能用”做成可解释工作流。

### 任务

- [ ] 实现统一输入的分批追加和增量处理。
- [ ] 实现链接提取状态、失败原因和降级入口。
- [ ] 建立规范化链接、内容指纹和 `sourceFamilyId`。
- [ ] 实现同源／疑似同源保守计数。
- [ ] 实现来源卡、必要短摘录、版本范围和缓存引用。
- [ ] 建立字段级 `FactField` 与证据关系。
- [ ] 实现绿／黄／红状态计算和冲突组。
- [ ] 实现版本更新后的字段级待复核与新旧差异。
- [ ] 实现“无法判断”列表和 1～2 个已核验同功能替换建议。
- [ ] 实现首页六项评分与前五多样性规则。
- [ ] 第一版自动来源只接官方更新、1～2 个公开数据源和公开网页搜索；博主内容通过用户链接、截图或字幕导入。

### 验收

- 两个转载同一公告的页面不会使事实变绿。
- 用户确认 OCR 不增加来源家族数。
- 失败来源不会静默消失，也不会参与核验。
- 新补丁到来后旧事实进入待复核，历史记录仍可查看。
- 搜索摘要不直接写入事实值。

工作量：L。

## 10. M6｜Obsidian 受控写回

### 目标

让网页工具与本地知识库形成闭环，同时保护已确认知识。

### 任务

- [ ] 在兼容桌面浏览器中让用户主动选择 Vault 文件夹并授予权限。
- [ ] 校验目标文件夹是否为预期 Vault，不修改 `.obsidian`。
- [ ] 生成 `ObsidianWriteBatch`，展示将创建、追加或生成差异的条目。
- [ ] 新知识默认写入 `AI待确认`。
- [ ] 高置信无冲突项默认勾选；低置信、冲突、版本不明项默认不选。
- [ ] 禁止删除和静默覆盖已确认笔记。
- [ ] 保留双链、YAML、来源、作者、日期和历史版本。
- [ ] 不兼容浏览器回退为可下载 Markdown 资料包。
- [ ] 写入失败保留待写批次并支持重试。

### 验收

- 用户可以在写入前看到准确目标路径和内容摘要。
- 取消单项不会影响同批其他条目。
- 已存在事实发生变化时只生成差异记录。
- 写入失败不丢失草稿，且可下载相同内容的 Markdown 包。

工作量：L。

## 11. M7｜发布数据 OCR 与复盘

### 目标

展示“知识库会成长”的第二条产品价值线。

### 任务

- [ ] 上传小红书数据截图。
- [ ] OCR 识别浏览、点赞、收藏、评论、分享等字段。
- [ ] 先展示识别结果，由用户确认或修改。
- [ ] 发布 7 天后生成完整复盘。
- [ ] 分析选题、标题、封面、内容和发布时间的可能问题。
- [ ] 评论区按问题、反对意见、补充经验、情绪反馈分类。
- [ ] 高频问题生成候选选题。
- [ ] 记录标题 3 次、排序 3 次、封面 5 篇等偏好学习门槛。
- [ ] 广告内容排除个人口吻学习。
- [ ] 为 Demo 提供匿名化真实复盘样例。

### 验收

- 未经用户确认的 OCR 数据不能进入复盘和知识库。
- 复盘使用“可能原因”，不把相关性写成确定因果。
- 单篇内容不会直接形成长期标题、封面或口吻偏好。

工作量：M～L。

## 12. M8｜在线 Demo 加固

### 目标

确保面试官打开链接即可理解项目，而不是先学习配置。

### 任务

- [ ] 首屏提供一句话产品介绍和“体验完整样例”按钮。
- [ ] 样例流程控制在 3 分钟内可走完。
- [ ] 提供“为什么这样设计”的产品说明抽屉，展示来源核验、锁页保护和知识库闭环。
- [ ] 加入空状态、加载状态、部分失败状态和错误恢复。
- [ ] 为 API 超时、额度用尽和实时来源失败提供样例回退。
- [ ] 测试主流桌面浏览器；不支持 Vault 连接时给出下载回退。
- [ ] 处理无障碍焦点、键盘操作、颜色对比和减少动态效果。
- [ ] 部署到支持 Next.js 服务端能力的平台。
- [ ] 添加隐私说明：Demo 不保存用户 Vault 和最终高清图片。

### 验收

- 新浏览器无缓存时可以完成完整样例。
- 真实 AI、搜索或 Vault 任一不可用时，核心 Demo 仍可体验。
- 页面错误信息使用普通用户能理解的语言。
- 仓库 README 能说明项目价值、架构、演示路径和本地启动方法。

工作量：M。

## 13. 第一轮开发范围

为了尽快形成作品集，第一轮只完成：

1. M0 工程骨架。
2. M1 匿名样例竖切。
3. M2 编辑器核心保护。
4. M3 PNG／ZIP 导出。
5. M8 中的首屏说明、错误回退和部署。

第一轮结束即可用于简历和面试演示。M4～M7 分阶段接入，用于证明真实 AI 与知识成长能力。

## 14. 推荐开发批次

### 批次 A｜看得见的产品

- 工程、五页面、设计 token。
- 匿名样例数据。
- 七页模板和编辑器。
- PNG／ZIP 导出。

### 批次 B｜真正的 AI 产品

- 统一 AI 适配层。
- 任务理解、观点、大纲、七页和发布文案结构化生成。
- 事实引用与导出阻塞。

### 批次 C｜知识库闭环

- 来源提取与事实核验。
- Obsidian 受控写入。
- 发布数据 OCR、评论分类与 7 天复盘。

## 15. 不做清单

- 不引入微服务和独立在线 Python 后端。
- 不先做账号体系和数据库后台。
- 不做任意拖拽自由画布。
- 不做实时协作、团队空间和评论审批。
- 不做全平台抓取、自动下载和自动发布。
- 不为每个 AI 任务接不同厂商 SDK；统一通过适配层。
- 不让 AI 生成带中文字、装备图标或角色的最终正文页。
- 不在第一轮实现全部内容模板和全部游戏。

## 16. 测试清单

### 单元测试

- Schema 校验、综合分计算、来源家族计数、事实状态、有效值合并、导出阻塞、版本迁移。

### 组件测试

- 锁页、字段保留、卡片换序、影响清单、错误状态、移动端预览。

### 端到端测试

1. 访客完整样例并导出。
2. 手改字段后整体重写，手改内容保留。
3. 黄色事实阻止正式导出。
4. 观点切换后逐页选择并解决冲突。
5. Vault 写入失败后下载 Markdown 回退。

### 视觉回归

- 七类关键页面固定截图对比，防止字体、卡片和图标位置在重构后失控。

## 17. 完成定义

一个任务只有同时满足以下条件才算完成：

- 功能符合 PRD 与 Schema。
- 有正常、空、加载、失败和重试状态。
- 不覆盖用户手改与锁定内容。
- 有至少一个自动化测试覆盖关键规则。
- 在匿名样例路径中可实际演示。
- README 或产品说明记录用户能看到的变化。

## 18. 面试讲解主线

1. 从“AI 写文案”重新定义为“可信游戏内容工作台”。
2. 用来源家族和字段级事实状态解决攻略过期与同源转载问题。
3. 用结构化生成和模板渲染解决中文成图不可编辑问题。
4. 用手改保护、锁页与影响清单解决 AI 重写不可控问题。
5. 用 Obsidian 与 7 天复盘展示知识和偏好如何逐步成长。
6. 用样例保底与有限实时生成控制 Demo 费用和稳定性。
