# 开发进展：输入理解与候选选题 v1.6

## 本轮结论

首页“分析我的输入”已经可用。用户可以输入一句灵感、一个公开网页链接，或在第一次分析后补充说明；系统会先展示事实边界和来源状态，再给出 3 个候选选题。

这条链路没有假装完成动态七页生成。候选选题目前是临时素材，可切换比较，但不会覆盖已经确认的“铲友装备课01”七页样例。下一条链路再把选中的候选接到研究卡和七页大纲。

## 已完成内容

1. 新增统一 AI 任务 `understand_input`
   - 输入：原始灵感或链接、手动补充、目标游戏、受众、创作目标和事实边界。
   - 输出：输入类型、创作意图、摘要、事实、来源、3 个候选选题、待补充问题和处理模式。
   - 候选选题包含综合推荐、搜索需求、收藏价值、长期有效性和新手痛点评分。

2. 事实与来源保护
   - 用户文字只作为“用户明确表达”，不自动升级为游戏事实。
   - 演示模式只识别网页地址，不声称已经读取正文。
   - 链接相关结论会标为“待核验”。
   - 在线模式返回的来源若没有出现在网页检索引用中，会自动降级为不可用。
   - 来源支持事实必须关联真实来源编号，否则不能标为已支持。

3. 费用与隐私控制
   - 没有密钥时继续使用免费演示分析。
   - 在线模式只有在输入包含链接，或明确出现“当前、今日、热点、版本、最新”等需求时才启用网页检索。
   - 普通灵感不会无故产生网页检索调用。
   - URL 中疑似 token、key、auth、signature、secret、code 的参数值会在发送给模型前隐藏。

4. 首页交互
   - 输入为空时按钮不可点击。
   - 分析过程中显示处理状态。
   - 分析结果分为事实边界、来源关系、3 个候选选题、评分详情和缺失问题。
   - 用户可以切换候选方向，并输入补充说明重新分析。
   - 分析失败时保留原输入，显示错误和手动补充入口。
   - 当前分析会随结构化草稿一起导出，但不会写进长期事实库。

## 验证结果

- 自动化测试：60 项全部通过。
- 静态检查：40 个必需文件、25 项规则全部通过。
- 构建：成功。
- 浏览器实测：一句“新手装备”灵感生成 3 个装备候选；公开链接显示“用户提供、正文未确认”；补充“阵容运营”后重新生成阵容判断与变阵选题；候选切换正常。

## 当前边界

- 演示模式不读取网页正文。
- 在线模式使用网页检索寻找公开来源，但不等同于通用网页抓取器。
- 截图 OCR、用户上传素材识别、动态研究卡和动态七页大纲尚未接入。
- 候选选题是临时素材，正式采纳和知识库写回将在后续链路完成。

## 技术依据

- OpenAI Responses API 支持文本或图片输入、结构化 JSON 输出和内置网页搜索：<https://developers.openai.com/api/reference/typescript/resources/beta/subresources/responses/methods/create>

## 下一步建议

把用户选中的临时候选接入“动态研究卡”：生成为什么值得做、可采取观点、事实与争议、待补来源，并让用户确认观点后再生成七页大纲。这样能够继续复用现有的观点冲突、字段保护、版本保护和导出能力。
