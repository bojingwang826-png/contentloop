# 开发进展：Obsidian 浏览器受控自动写回 v4.3

日期：2026-09-05

## 用户目标

接入本地 Obsidian 知识库，把网站中的当前项目草稿与后续改动自动写入，同时持续记录该项目的开发、发布和验证情况。

## 实现方式

- 沿用此前确认的浏览器 File System Access 方案。首次点击“连接 Obsidian”，用户主动选择 Vault 根目录并授予读写权限。
- 连接前验证所选目录存在 `.obsidian`；程序只读取该标志，不创建、不修改该目录。
- 文件夹句柄保存在浏览器 IndexedDB。权限仍有效时重新打开网站会恢复连接；浏览器要求再次授权时显示“重新授权 Obsidian”，不会假装同步成功。
- 网站状态变化后防抖 900ms，将完整当前草稿覆盖写入 `AI待确认/铲友创作台自动同步/当前草稿.md`，并在同目录追加同步时间与步骤记录。
- 快照包含输入、已确认截图的文字结果、选题与研究项目、大纲、七页内容、发布文案和命名版本元数据；不保存高清截图、AI 访问码或服务端密钥。
- 自动内容始终标为 `ai-pending`，不会覆盖游戏事实库、观点库及其他正式笔记。
- 顶栏和导出页提供连接状态与操作入口；支持断开连接，断开不会删除已写入笔记。

## 两种同步的边界

1. **网站内容自动写回**：只在用户授权过的 Chrome/Edge 等兼容浏览器中运行，浏览器必须能访问本地 Vault。公开网站的服务端不能直接读取本机文件。
2. **项目开发记录同步**：由开发协作过程在每次实质变更后写入 Vault 的“产品探索”，遵循[[知识库持续同步规则]]。它不依赖网站是否打开。

## 验证

- 自动测试 175 项通过，其中新增测试覆盖待确认标记、七页与发布文案完整保留、正文代码围栏隔离。
- 静态检查通过：46 个必需文件、30 项规则。
- 生产构建通过。
- 真实文件夹选择必须由用户在浏览器中主动完成，自动测试无法替代该权限操作；发布后需执行一次真实 Vault 验收。

## 发布前真实验收

1. 点击顶栏“连接 Obsidian”，选择 `游戏内容创作知识库` 根目录。
2. 修改任一页文字并等待约一秒。
3. 在 Obsidian 打开 `AI待确认/铲友创作台自动同步/当前草稿.md`，确认修改可见且正文完整。
4. 刷新网页，确认状态恢复；若浏览器收回权限，点击重新授权后继续写入。
5. 断开连接，确认已有笔记仍保留且后续网页修改不再写入。

## 限制

- Safari、Firefox 或隐私模式可能不支持或不保留文件夹句柄，界面会明确提示使用最新版 Chrome/Edge。
- Vault 移动、改名或操作系统收回权限后需要重新选择/授权。
- 当前采用“最新完整快照＋同步日志”，不是每次按键都创建一份永久历史；网站自身命名存档仍保留在快照元数据中。
