# 开发进展｜命名存档管理 v1.0

## 本次完成

- “保存当前版本”升级为“命名保存”，点击后先填写可理解的存档名称，不再自动生成难辨认的系统名称。
- 名称会清理多余空格并限制为 40 个字，提供“封面定稿、面试演示版”等用途提示。
- 历史面板同时展示命名存档和自动版本，并用文字标签区分，避免只靠颜色判断。
- 支持按选题、研究、大纲、编辑、导出五个步骤筛选，列表同步显示两类版本数量。
- 命名存档可以改名；自动版本保持只读，只能恢复，避免误改系统历史。
- 删除命名存档前显示原因和影响范围，必须二次确认；删除只移除存档入口，不影响当前草稿。
- 删除后提供“撤销删除”，也可以关闭恢复提示；危险操作使用独立样式和清楚文字。

## 关键产品决策

- 自动版本解决“误操作恢复”，命名存档解决“里程碑留档”，两者不能混成同一种记录。
- 存档名称由用户决定，系统只给贴合当前步骤的默认建议。
- 删除只开放给命名存档；自动版本由 20 个上限滚动管理，减少用户理解成本。
- 改名、筛选和删除只改变版本元数据，不修改七页草稿和当前工作流。
- 手机端把行内表单和操作按钮改为单列／网格，输入与按钮保持至少 44px 高。

## 验证结果

- 40 项自动测试全部通过，新增覆盖名称规范、改名边界、删除、撤销删除和关闭提示。
- 静态检查和生产构建通过。
- 实际走通“命名保存 → 改名 → 按选题筛选 → 删除确认 → 撤销删除 → 清理验收存档”。
- 目视检查确认命名存档、自动版本和危险操作层级清楚。
