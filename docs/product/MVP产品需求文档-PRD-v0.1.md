# 游戏图文创作工具｜MVP 产品需求文档 v0.1

## 1. 一句话定义

面向游戏内容创作者的“选题研究＋可信内容生成＋七页图文编辑＋Obsidian 沉淀”工作台：先帮助用户发现值得写的金铲铲选题，再把可核验资料变成可编辑、可导出的小红书图文。

## 2. 项目背景

### 用户背景

- 求职方向：AI 产品经理。
- 技术能力：能使用 Codex、Claude Code 和少量 Python，做过简单原型与需求文档。
- 项目目的：形成有真实产品闭环、可供面试官直接体验的在线 Demo，并用少量真实发布验证效果。
- 投入约束：单人、低成本、优先做清晰完整的核心流程，不追求大而全。

### 需要解决的问题

1. 不知道今天应该发什么，缺少能解释“为什么值得写”的选题助手。
2. 游戏攻略容易混入旧版本、转载同源信息和无法核验的结论。
3. 普通 AI 文案没有稳定口吻，也很难直接变成手机可读的七页图文。
4. 创作资料、博主方法、个人修改和发布结果没有形成可持续成长的知识库。

## 3. 目标用户与首发内容

### MVP 使用者

单个游戏内容创作者。第一阶段主要是用户本人，面试官以访客身份体验预生成样例。

### 内容读者

会照着阵容抄作业，但不会根据来牌、装备和局势调整；关注版本强势内容、想提高理解与上分效率的金铲铲玩家。

### 首发游戏与内容

- 首发游戏：《金铲铲之战》。
- MVP 内容模板：收藏型新手教程、时效型版本攻略。
- 首个端到端样板：“铲友装备课 01｜金铲铲装备合成终于看懂了”。

## 4. 产品目标与非目标

### 产品目标

1. 让用户在 10～15 分钟内，从选题进入可编辑的七页图文并完成导出。
2. 让每个推荐选题都能解释热度、差异空间、可用观点和证据状态。
3. 让发布内容与内部来源、版本和事实字段保持可追溯关系。
4. 让知识库通过用户修改、来源收藏和发布复盘逐步理解账号，但不根据单次行为过度学习。
5. 让在线 Demo 在没有真实账号、Vault 或实时模型额度时仍能走完整流程。

### MVP 非目标

- 不做 Canva 式自由画布。
- 不做全平台自动爬虫或小红书自动发布。
- 不做多人协作、注册、邮箱找回和复杂权限系统。
- 不做跨设备临时草稿同步。
- 不做游玩体验、新闻汇总、广告图文和其他游戏专属模板。
- 不做交互式装备查询、自动抠图或自动抓取全部官方素材。
- 不承诺商业使用素材授权；MVP 仅用于个人作品集与内容验证。

## 5. 核心价值排序

1. 选题聪明：发现机会并解释为什么值得写。
2. 内容可信：区分事实、观点、争议、版本和来源家族。
3. 图文可用：生成手机可读、逐页可改、可以直接下载的七页图文。
4. 知识成长：保留来源、修改和复盘信号，逐渐形成稳定账号方法。

## 6. 产品原则

- 网页工具是主要工作台，Obsidian 是后台内容大脑。
- 先研究和确认大纲，再进入排版；不直接生成不可编辑的成品图。
- AI 输出结构化内容，React 模板负责中文字、素材、布局和 PNG 导出。
- 缺少真实经历时明确使用资料整理口吻，不伪造亲测。
- 用户提供的单个公开网页解析成功后即可进入选题与研究链，不要求第二站点或额外确认。
- 用户确认 OCR 或手动补充后可直接使用；具体版本数值仍需核对页面日期与适用赛季。
- 历史、来源和用户修改不静默覆盖；变化先展示差异。
- 默认采用安全、可逆、可解释的产品方案；重大方向、费用、权限和不可逆操作再询问用户。

## 7. 核心流程

`首页输入／选题推荐 → 任务理解确认 → 研究与事实检查 → 选择主要观点 → 七页大纲确认 → 图文编辑 → 导出发布包 → 写入知识库 → 7 天后复盘`

### 主流程完成定义

- 用户可以直接选择推荐选题，也可以输入一句模糊想法、链接和截图。
- 生成前可以看到系统理解、信息缺口、证据状态和观点分歧。
- 大纲经确认后才生成页面。
- 用户可以锁页、改单字段、局部重写和整体重写。
- 通过导出检查后得到七张 PNG、发布文案、标签和结构化草稿。
- 确认后的知识写入 Obsidian；临时编辑状态保存在当前浏览器。

## 8. 页面与功能需求

## 8.1 首页

### 页面模块

- 今日值得做的 5 个选题。
- 当前版本热门阵容。
- 统一创作输入框。
- 最近草稿和预生成样例入口。

### 统一输入

- 一次任务支持一句想法、最多 5 个链接和最多 10 张截图。
- 超过上限时保留已选内容并允许分批追加。
- 新批次只分析新增素材；发生冲突时只复核受影响字段。
- 支持链接、网页正文、图片、数据截图、视频字幕和转写文本。

### 任务理解卡

识别后先展示可编辑卡片：

- 想解决的问题。
- 系统推测的主要内容类型。
- 已识别来源及失败项。
- 缺少的信息。
- 最多 3 个真正影响结果的追问，每题包含原因与标明为系统建议的推荐答案。

用户可以确认、修改或跳过。跳过项标记为未知，AI 不得脑补。

### 今日选题排序

- 展示综合分与六个子分：热度、增长速度、时效性、差异空间、证据充分度、账号匹配度。
- 默认权重：15%、20%、15%、15%、20%、15%。
- 常青新手教程额外判断搜索需求、收藏价值、长期有效性和新手痛点，收藏价值权重最高。
- 阵容数据超过 24 小时标记“非今日数据”，超过 72 小时不参与今日排序。
- 相同主题与角度进入 14 天重复冷却；新版本或新证据可以解除。
- 前五最多出现两个相同内容类型。

每张选题卡说明推荐标题方向、为什么值得做、差异空间、可采取观点、关键证据、风险和素材难度。

## 8.2 选题研究

### 默认展示层级

第一屏展示：

1. 为什么值得做。
2. 2～3 个可选观点及各自适用情况。
3. 关键证据与绿／黄／红状态。
4. 系统推荐站位及理由。

原始链接、完整摘录、来源家族和引用关系折叠，需要时展开。

### 来源处理

- 搜索摘要只用于发现线索，不直接成为事实。
- 链接失败按“重试一次 → 同源公开替代页 → 请用户粘贴正文／上传截图／更换链接”降级。
- 失败来源保留在清单中，不能静默忽略。
- 用户粘贴的正文、截图、同源公开版本与原链接默认属于同一来源家族。
- 不可读取来源不参与观点蒸馏、事实核验和独立来源计数。

### 观点选择

- 进入大纲前选择 1 个主要观点和最多 1 个补充提醒。
- 补充提醒只用于适用边界、存在争议或反例，不发展成第二条主线。
- 系统自动把补充提醒放在最相关页面，以短提示框呈现，不独占整页。
- 主要观点确认后成为文章级锁定项；整体重写不改变它。

## 8.3 大纲确认

- 展示七页页面任务、顺序、重点内容、所需素材和事实引用。
- 支持调整页序、页面重点与模板选择。
- 用户确认后进入排版生成。
- 模板改变或主要观点改变时生成影响清单，不静默覆盖已确认内容。

## 8.4 图文编辑

### 编辑方式

- 左侧或中央显示七页卡片，右侧显示当前页字段与实时预览。
- 支持标题、正文、标签、素材、配色、字号和重点样式的有限编辑。
- 不开放元素任意拖拽、旋转和自由缩放。
- 页面预览与 PNG 导出使用同一 3:4 React 组件。

### 保留与重写

- 手动修改字段自动标记“已保留”。
- 锁定整页后，该页全部字段不参与重写。
- 普通重写只更新未保留、未锁定内容。
- 整体重写保留主要观点、手改字段、锁页和手动卡片顺序。
- 切换主要观点时先列出受影响页和原因，用户逐页选择保留或重写。
- 保留内容与新观点直接矛盾时允许继续编辑，但阻止正式导出。
- 每次 AI 重写前建立版本点，支持撤销、重做和恢复；最多保留 20 个自动版本，命名版本不清理。

### 装备卡排序

- 系统按页头问题给出初始顺序，但不显示强度名次。
- 用户通过上移、下移调整；手动顺序默认保留。
- 编辑器可展示排序依据，导出图片不展示。
- 同类换序累计 3 次后才询问是否形成对应问题类型下的长期偏好。

## 8.5 导出与沉淀

### 发布包

- 七张 3:4 PNG，可单张下载或 ZIP 下载。
- 文件按页码命名。
- ZIP 同时包含结构化草稿、发布正文和话题标签。
- 生成 3 个标题候选：搜索关键词型、痛点共鸣型、收藏价值型。
- 生成 1 版 150～250 字发布正文和 5～8 个相关标签。
- 标题、正文、标签可以独立重写，不触发图片重生成。

### 导出检查

- 检查字体与素材是否加载、文字是否溢出、图片是否缺失或低清。
- 检查本篇实际引用的事实字段，不用未引用字段阻塞导出。
- 黄色引用允许内部预览，但阻止无标识正式导出；可以导出带“待核验”的内部草稿。
- 红色事实禁止进入生成。
- 阻塞清单展示页码、装备或内容对象、字段、状态、原因和跳转入口。
- 观点冲突、版本过期和素材问题也进入同一可操作清单。

### Obsidian 写回

- 经用户确认的来源、事实、观点、表达方法、内容记录和复盘写入对应知识区。
- AI 新提取内容先进入 `AI待确认`；高置信无冲突项可默认勾选，低置信或冲突项默认不选。
- 已确认事实只能生成差异并等待确认，不能静默覆盖。
- 浏览器无法连接 Vault 时下载 Markdown 与图片资料包。

## 9. 两类七页模板

## 9.1 收藏型新手教程

适用于装备合成、装备分配、替代装备等长期痛点。结构可以按主题变化，但首个样板固定为：

1. 封面。
2. 完整普通装备合成树。
3. 物理输出。
4. 法术与启动。
5. 攻速与持续输出。
6. 坦度与生存。
7. 可收藏判断口诀。

第 3～6 页统一为“一个新手判断问题 → 三张纵向装备卡 → 一句整页避坑提醒”。

## 9.2 时效型版本攻略

1. 封面与当前版本结论。
2. 为什么火：最多 2 个已核验数字，证据不足时只写趋势。
3. 阵容组成与参考站位。
4. 主 C、主坦装备与当前阵容平替。
5. 最多 4 个节点的运营时间线。
6. 3 个“触发信号＋应对动作”分支，至少一条别硬玩条件。
7. 3～5 条一页抄作业口诀。

## 10. 首个样板验收范围

### 内容范围

- 系列：铲友装备课 01。
- 标题：金铲铲装备合成终于看懂了。
- 只覆盖普通散件和常规成装；排除金铲铲、金锅锅、纹章、神器、光明装备和限时模式装备。
- 用户已确认普通配方跨模式一致，但正式导出仍按事实字段执行版本核验。
- 第 2 页展示完整合成树；第 3～6 页共展示 12 件重点成装；第 7 页为四步判断路径。

### 12 件重点装备

- 物理输出：无尽之刃、巨人捕手、最后的轻语。
- 法术与启动：珠光护手、朔极之矛、大天使之杖。
- 攻速与持续：鬼索的狂暴之刃、海妖之怒、泰坦的坚决。
- 坦度与生存：石像鬼石板甲、狂徒铠甲、日炎斗篷。

每张首篇装备卡只显示官方图标、装备名、合成路径、一句“什么时候合”和最多两个抽象定位标签；不展示具体英雄、平替和推荐等级。

### 第 7 页口诀

`定主 C → 辨伤害 → 看启动 → 保前排`

首次出现“主 C”时解释为“队伍里的主要输出英雄”。每页最多解释一个术语，其余优先改成白话。

## 11. 视觉与口吻

### 视觉

- 金铲铲原生感：深色、金色、棋盘与卡牌氛围。
- 封面视觉较强，正文克制并优先手机可读。
- 官方装备图标保持原样、比例和颜色；AI 只生成背景、纹理和装饰。
- 功能分类可以用固定颜色，但必须同时有文字标签。
- 每页保留系列名、页码和用户填写的账号名。
- 首篇封面或第 7 页合计最多 1 个表情，第 2～6 页不用表情。

### 个人口吻

- 人设：比读者多懂一点的游戏搭子，“这套我帮铲友们研究明白了”。
- 自然聊天为主，热情但不端着、不冒犯新手。
- 默认称呼“铲友们／新手玩家”，自然提醒中偶尔使用一次“你”。
- 没有实测时写成资料整理，不使用“亲测多少局”等虚构经历。
- 允许“一图看懂、终于搞明白”等情绪化夸张；可验证数字、胜率和必然上分承诺必须有证据。
- 不复制博主独特原句和固定口头禅。

## 12. 知识库结构与存储边界

### Obsidian 永久保存

- 版本事实、来源元数据、来源家族和必要短摘录。
- 博主档案和可复用表达方法。
- 观点、选题归档、个人口吻与标题偏好。
- 已发布内容、低清预览、7 天数据和复盘结论。
- 完整原文／字幕／转写缓存的引用、摘要和指纹。

### 项目本地缓存

- 完整网页副本、字幕、转写和 OCR 原始大文件。
- 高清图标和高清导出图。
- 30 天未使用后只标记可清理；用户确认后进入 7 天回收站，再永久删除。

### 浏览器本地

- 临时草稿、当前编辑状态和最近 20 个自动版本。
- 使用 IndexedDB 并保存 `schemaVersion`。
- 支持单个项目包导入导出；不保存 API 密钥、完整 Vault 或高清导出图。

## 13. 学习与复盘

- 学习信号：锁页、重写、删除、手改、排序、标题选择、标签调整、收藏来源和发布数据。
- 用户上传小红书数据截图后，AI 先展示 OCR 结果，用户确认后入库。
- 发布 7 天后形成复盘，收藏率作为最重要表现信号之一。
- 分别判断选题、标题、封面、内容和发布时间，不能把所有结果归因于某一个因素。
- 评论区自动分为问题、反对意见、补充经验和情绪反馈；高频问题生成候选选题。
- 标题偏好按长期教程、版本热点、具体阵容、体验观点四类隔离；累计 3 次相似行为并经确认才形成长期偏好。
- 封面倾向至少累计 5 篇同类内容后才提示。
- 广告内容不参与个人口吻和自然内容偏好学习。

## 14. Demo 与权限

### 访客模式

- 免注册。
- 使用匿名化预生成热点、研究结果和七页样例。
- 提供少量实时 AI 次数，额度用完仍能编辑、锁页、使用样例重写和导出。
- 不连接真实 Vault，不展示真实发布数据。

### 个人模式

- 简单密码保护。
- 可连接本地 Obsidian Vault、导入真实素材并执行受控写回。
- 密钥只保存在服务端环境变量或密钥管理中。

## 15. 技术与非功能要求

- 一个 TypeScript 全栈项目，建议 Next.js App Router。
- AI、搜索、转写、频率限制和密钥只在服务端处理。
- 页面只调用统一 AI 适配层，不绑定单一模型厂商。
- AI 文字输出必须经过固定 JSON Schema 校验；失败自动修复或重试一次，仍失败则保留旧稿。
- PNG 和 ZIP 在浏览器生成，服务器不保存用户导出图。
- 桌面优先，同时保证编辑预览能够模拟手机阅读。
- 所有异步任务有加载、失败、重试和保留旧结果状态。
- 任何失败都不能静默丢失来源、用户输入或手改内容。

## 16. MVP 验收标准

### 核心闭环

- [ ] 面试官无需注册即可从预生成选题走到七页导出。
- [ ] 个人用户可以输入想法、链接和截图并确认任务理解。
- [ ] 研究页能展示观点、来源和字段级事实状态。
- [ ] 至少支持两类模板，并自动推荐模板。
- [ ] 七页内容可以逐页编辑、锁定、局部重写和恢复版本。
- [ ] 正式导出能阻止未核验字段、观点冲突、文字溢出和素材缺失。
- [ ] 导出包含 7 张 PNG、3 个标题候选、正文、标签和结构化草稿。
- [ ] 兼容浏览器可以受控写回 Vault；不兼容时可以下载 Markdown 包。
- [ ] 能上传一张发布数据截图，确认 OCR 后生成第 7 天复盘记录。

### 首篇样板

- [ ] 七页结构与 12 件装备符合已确认大纲。
- [ ] 装备图标未被 AI 重绘、改色或变形。
- [ ] 第 2 页完整合成树可放大查看。
- [ ] 第 3～6 页在手机尺寸下可读，无文字溢出。
- [ ] 首篇实际展示字段均通过导出核验，或只能导出带待核验标识的内部草稿。

## 17. 核心事件与演示指标

MVP 至少记录以下匿名事件：

- 选择／放弃推荐选题。
- 确认或修改任务理解。
- 选择主要观点与补充提醒。
- 修改大纲。
- 锁页、重写、恢复版本和手改字段。
- 导出成功、导出被阻止及阻止原因。
- Obsidian 写回成功、失败和回退下载。
- 上传并确认发布数据。

作品集展示重点：从模糊想法到可发布图文的完成时间、被事实检查拦截的问题、用户修改被保护的比例，以及知识库沉淀的可追溯关系。

## 18. 主要风险与处理

| 风险 | MVP 处理 |
| --- | --- |
| 实时来源不稳定 | 样例保底、展示最后成功时间、允许手动补充 |
| 版本事实过期 | 绑定版本与日期，新补丁触发字段级待复核 |
| 单一来源过期或错版 | 保留原始 URL、页面日期和适用赛季，发布前提示核对 |
| AI 改坏用户内容 | 手改字段与锁页保护、重写前版本点 |
| 中文成图不可编辑 | AI 输出 JSON，模板渲染文字与素材 |
| Demo 模型费用失控 | 预生成样例、访客限额、频率和每日总额 |
| 游戏素材版权 | 仅作品集验证、保留来源、商业化前重新审查 |
| 单篇数据导致错误学习 | 标题 3 次、封面 5 篇等最低样本门槛 |
